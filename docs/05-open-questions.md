## Decided

| # | Topic | Decision | Rationale |
|---|---|---|---|
| Q1 | Default units in the US | **yards + MOA** (F-21 unchanged) | The user can change distance and angle independently (F-20). A US shooter who uses mrad switches to mrad with one setting. |
| Q2 | "Staying on target" | **3 states**: red if error > half-size; orange if error > threshold × half-size (default 50 %, adjustable); green otherwise (F-32, F-53) | Red = aiming at the center of the gong, with no wind, parallax alone takes the shot off the gong. Orange = the shot stays on, but parallax eats more than half of the center-to-edge margin. |
| Q12 | Target shape | **No shape choice**: the entered size is the smallest dimension (diameter, side, smaller side of a rectangle) (F-50) | Conservative in every direction, no extra field, avoids over-engineering. |
| Q3 | Eye position | **3 levels**: Excellent (1/4), Good (1/3, default), Worst case (1). Segmented control on the result screen + preferences. The "Custom (δ mm, M)" mode is removed (F-31) | Worst case raises false alarms. Having the choice on the result screen shows the effect of head position directly. |
| Q4 | V1 languages | **en + fr only** in V1 (F-13). Glossary of domain terms (`07-i18n-glossary.md`). Play Store listing only in the app's languages (F-14). de, es, it are candidates for V1.x, to be chosen from Play Store statistics | The risk is badly translated shooting jargon, not volume (~150 strings). Only en and fr can be checked in-house. |
| Q5 | Scope profiles | **One single global profile in V1** (objective diameter, F-30). Several scopes with a choice per match: to reconsider after V1 | KISS: most shooters use a single scope in a match. |
| Q6 | Dial calibration | **No calibration**, neither in V1 nor planned in the data model. The app displays a distance; 100 m is 100 m | Knowing how one's dial maps to distances is the user's job. |
| Q7 | Setting rounding | **To the nearest meter (or yard)** (NF-07 unchanged) | Consistent with Q6. A fixed 5 m step would be too coarse up close (25 → 30 m changes parallax a lot) and useless far away. |
| Q8 | Sharing matches | **JSON export/import** through the phone's share sheet (F-65). No QR code, no share link | A match is usually prepared the day before, when the match book arrives, so remotely: a QR code only helps in person. A link would require a server (NF-04). |
| Q9 | Web version | **Postponed to V2.** V1 = Android only. The domain stays a pure Kotlin module and the test cases a neutral JSON file. The choice between KMP and a TS rewrite + framework will be made when V2 starts (`04-architecture.md`) | The real target is Android, and this halves the workload. Preparing and checking a match happens on a phone. |
| Q10 | App name | **Parallax Planner**, package **`com.cussou.parallax`** | "Parallax" helps Play Store search and speaks to every discipline; "Planner" covers both the quick calc and match preparation. Neutral, brand-free package, because it is permanent. Availability to check (Play Store, INPI, EUIPO) before publishing. |
| Q11 | Icon | **Double reticle** (`ic-double` in `06-name-and-icons.md`), as an Android adaptive icon | Chosen by the user from fine-line versions of the Zero Shift idea: the ghost reticle and the realigned one show what parallax is. It replaced the P-reticle monogram, whose P did not read at a glance. Can be changed at any time through an update. |
| Q13 | Where a reversed range (min > max) is swapped | **In the presentation layer.** The domain function `optimalSettingForRange` requires 0 < min ≤ max and rejects anything else (F-05) | The swap has to be shown to the user, so the screen must know about it anyway. The domain stays a plain formula with one precondition. |
| Q14 | Number display and input details | Displayed values round **half up**, settings have **no thousands separator**, and number fields accept **a dot or a comma** as decimal separator in every language (NF-07) | Half up is what a shooter expects from a rounded figure. A separator in "1,234 m" reads as a decimal in French. Numeric keyboards do not always offer the locale's separator. |
| Q15 | Quick calc input details | The 5–2000 limits apply to **the number as typed, in the current distance unit** (5–2000 m or 5–2000 yd). A reversed range is computed in the right order and flagged by a message, **without rewriting the fields**. When the distance unit changes, the typed range is **converted** (100 m becomes 109.4 yd), rounded to 0.1 (F-05, F-25) | "Between 5 and 2000 yd" is a message a shooter can read; the exact yard equivalent (5.47–2187) is not. Rewriting a field while the user is typing in it gets in the way. Keeping "100" after a switch to yards would silently change the range. |
| Q16 | Target list details | Targets are entered in a **bottom sheet** (not inline). The list is **always sorted by distance**. A stage holds **at most 50 targets** and a label **at most 20 characters**. Editing a target without touching its distance field **keeps its exact stored distance** (F-50, F-25) | The UX doc allowed inline or bottom sheet; one editor for adding and editing is simpler. 50 is the limit the exact algorithm is documented for (`02-calculations.md` §4). The distance field shows a rounded value, so reading it back would move the target slightly after a unit change. |
| Q17 | Match storage | **One JSON file per match**, in the export format, instead of Room. **Targets have no id** in the file. In the match list, dated matches come first, most recent first, then the others by name | The architecture doc allowed "Room (or a JSON file)": files mean one format and no database schema to migrate. Nothing uses a target id; the list position is enough. The list order was not specified. |
| Q18 | Import details | An imported match **always gets new ids**: it is added, never replaces a match, even the one it was exported from. Import goes through the **system file picker**, which accepts files of any type; the app does not register as a target of "Open with" or "Share to". A file over 1 MB is not read | Replacing a match silently would lose the user's own changes; two matches with the same name are easy to tell apart and delete. Files received through messaging apps often come without the JSON type. One way in is enough for V1; "Open with" can be added later if teammates ask for it. |
| Q19 | Simple and advanced modes | **A single mode.** The advanced screen is the only one: targets, matches, the bottom bar and the target settings are always there. A "Clear all" button on the targets goes back to a plain range in one tap (F-57). F-40 and F-41 are removed | Decided by the user after using the advanced screen: without targets it already works like simple mode, so the switch only hid things. A toggle on the main screen was considered and rejected: a setting changed once does not belong on the most used screen, and a stray tap with gloves would hide the targets on the firing line. One mode means less code, fewer tests and one app to explain. |
| Q20 | Accent color choice | **Ten accents** in the settings, azure by default: the five blues, cyan and violet, the first orange and a brighter one, and lime green. Shown as round swatches, the name of the chosen one written. The **launcher icon stays azure**. Electric and royal blue are lightened to reach AA on the result card | The user likes azure for the icon but wanted a choice in the app, with every color proposed in the comparison. Lime green is kept although the setting can then read like the "on target" status: statuses always carry an icon and a text (F-54). Changing the launcher icon with the accent would need an activity alias per color, for little gain. |
| Q21 | License and community files | Code under the **Zero-Clause BSD** license (0BSD). The bundled fonts keep the SIL Open Font License. **Contributor Covenant 2.1** as code of conduct. Conduct and security reports go through GitHub **private vulnerability reporting**, not an email address | The user asked for the most permissive license. 0BSD lets anyone use the code for anything, without even keeping the notice, and works in every jurisdiction, unlike a public-domain dedication such as the Unlicense or CC0, which French law does not fully recognize. Private reporting gives a private channel without publishing a personal address. |
| Q22 | When the CI runs | On **pull requests** and **by hand** (Actions tab, any branch), not on pushes to main. Two jobs in parallel: unit tests, lint and a debug build (a few minutes), and the UI tests on an API 34 emulator with a cached snapshot. The release workflow will run the tests again | The maintainer usually pushes to main after running every test locally, so a CI on each push would only repeat them. Pull requests from other people, or from a branch when in doubt, get the full check. The repository is public, so GitHub Actions minutes are free. Gradle is cached through `actions/setup-java` rather than `gradle/actions`, whose v6 caching is no longer open source and requires accepting Gradle's terms of use. |
